## 1. Тестовые главы — одной командой

```bash
.venv/bin/python -m kurs cost path/to/test_chapter.md          # прогноз цены, бесплатно
.venv/bin/python -m kurs run path/to/test_chapter.md --max-usd 0.5 --video --vision
```

`run` делает всё: единицы → слой и покрытие → дополнение (заблуждение, «как сейчас», линза неэффективности, не сказанные единицы) → маршруты → задания → рисунки → проверку → (с `--video`) шортс и разбор по маршрутизации анимацией Remotion → курс с роликами на своих шагах → манифест → строку в `build/metrics.csv`.
На сценарии роликов идёт остаток `--max-usd` после слоя (≈ $0,01 за ролик); денег нет — сценарий по правилам.
`--vision` после сборки курса смотрит все кадры рисунков моделью со зрением (≈ $0,02 на главу); подтверждённо неверный рисунок от модели заменяется простой схемой, курс собирается заново.
Обрыв сети не теряет работу: повторный запуск доделывает только пропущенные запросы.
Колонтитулы (короткая строка, повторённая на трёх и более страницах) модель не видит; в покрытии они идут с причиной `page_furniture`. Утверждение, потерявшее оговорку автора («могут», «часто», «около 30 м»), условие или отрицание, уходит на правку модели вместе с ошибками; правка, от которой замечаний стало больше, откатывается. Цитата, обрезанная так, что не держит утверждение («что служит причиной…»), кодом расширяется до целого предложения автора.

Проверить результат:

```bash
.venv/bin/python -m kurs check <id> --strict       # смысловые замечания как ошибки — посмотреть глазами
.venv/bin/python -m kurs fuzz <id>                 # доля пойманных внесённых ошибок, фон ложных тревог
node video/qa_course.mjs build/<id>/course/index.html
.venv/bin/python -m kurs vision <id> --max-usd 0.05   # рисунки глазами модели: все кадры, два прохода; --apply снимает подтверждённо неверные
```

## 2. Правка факта человеком (≤ 30 чел.-мин на главу)

1. Исправить утверждение в `build/<id>/layer.json` (текст, цитату, страницу).
2. `kurs plan <id>` — что устарело: утверждения, задания, ролики, курс.
3. `kurs rebuild <id> [<node_id>] --video` — пересборка страницы и ролика одной командой без модели (`KURS_LLM_OFFLINE=1`): сломанные задания заменяются заданиями по правилам того же шага; в сохранённом сценарии ролика меняются числа, изменённое утверждение звучит новой формулировкой; ролик рендерится заново и встаёт на свой шаг; курс проходит приёмку, манифест обновляется. Глава из `run --domain drilling` пересобирается с тем же доменным пакетом.
4. Записать правку в `manual_edits.csv` и закоммитить: журнал правок должен совпадать с `git log`.

## 3. Ролики

```bash
.venv/bin/python -m kurs video <id> --node <node_id> --format 9:16 --max-usd 0.05   # ролик по назначенному узлу — сразу в курс
.venv/bin/python -m kurs video <id> --max-usd 0.05              # шортс 9:16 и разбор 16:9 по маршрутизации
.venv/bin/python -m kurs video <id> --import build/videos/<video_id>   # ролик, собранный на другой машине, — в курс
.venv/bin/python -m kurs video <id> --engine html --dry         # старый путь: сценарий кадрами-слайдами
```

Ролик по узлу (шаблон `NodeStory`): сценарий пишет модель (крючок, механизм, вопрос-предсказание, ответ, граница, данные, перенос), код проверяет длину фраз, формулы, числа и порядок, судья сверяет смысл с карточкой. Кадры рисунка узла сменяются по репликам, пауза предсказания 1,5 с, финал держится на экране.
Сценарий хранится в `build/<id>/scripts/<узел>_9x16.json` — правится руками, `rebuild --video` берёт его.
Каждый ролик: `build/<id>/video/<video_id>/` — `<video_id>.mp4`, `poster.png`, `passport.json`; запись в `build/<id>/videos.json` ставит его на шаг курса.
Отчёт о покрытии узлов шаблонами сцен для сдачи — `build/<id>/template_coverage.md` (и `.json`): каждый видеоёмкий узел по маршрутизации, шаблон NodeStory с рисунком узла, модель состояния (расчёт по параметру, смена состояний, раскрытие по частям, статичный) и статус «закрыт» или «нужен новый». `run` пишет его всегда, с роликами и без. Подробности по всем узлам — `build/<id>/scene_coverage.json`.
Пункты чек-листа физики, которые код не проверяет, помечены в паспорте — их подтверждает специалист при просмотре.

## 4. Модуль «Закладки»

```bash
# слепой прогон: код + три взгляда модели + кадры моделью со зрением + два судьи
.venv/bin/python -m kurs.review <путь>/package.json -o build/review/blind.json --max-usd 0.4
# только ПОСЛЕ сохранения файла:
python <путь>/score_review.py build/review/blind.json <спрятанный_путь>/key.json
```

- Ответ проверяется по `review_output.schema.json` (ищется рядом с пакетом и в `пакет_вводных/02_модуль_проверки/`); ошибки схемы печатаются, код выхода 1.
- На один `target` — одно замечание: доказанное кодом важнее модели, тяжёлое — лёгкого.
- Каждый элемент читают три взгляда, каждый кадр — два, каждого кандидата решают два судьи. Замечание остаётся, если его увидели не меньше двух взглядов и подтвердил хотя бы один судья, либо доказал код и подтвердили оба судьи. Ход решения — в `blind.trace.json`.
- Замер на контрольном пакете (слепой прогон 26.11): найдено 19 из 21 ошибки (92 % по весу), ложных тревог 1, 6 минут, $0,18.
- Без `--max-usd` (или с `--no-llm`) работают только проверки кодом — это бесплатный нижний предел.
